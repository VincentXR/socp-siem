# SOCP 工作台界面重设计规范

状态：设计参考，视觉令牌与部分交互已落地；原型不代表当前产品的全部实现。
当前导航以 `frontend/apps/workbench/src/app/navigation.ts` 为准：安全运营、接入与数据、
检测与响应、调查上下文、合规与报表。分组支持折叠，接入默认展开；下文原型分组仅用于设计比较。
范围：工作台外壳 + 三个最高频页面（态势总览、告警队列、日志检索），浅色/深色双主题。
可视化原型：[`prototype/index.html`](prototype/index.html)（可直接在浏览器打开，含交互）。

---

## 1. 设计立场

现有工作台是 GitHub 风格的 Element Plus 应用，功能完整但视觉趋于默认。本次重设计不是换皮，而是把
「仪表」和「研判台」两种气质分开：**结构靠秩序，判断靠数据，颜色只承担语义。**

四条原则，冲突时按顺序让位：

| # | 原则 | 具体约束 |
|---|---|---|
| 1 | 数据优先于装饰 | 无渐变背景、无发光、无投影卡片；分隔用 1px 发丝线，层级用底色差而非阴影 |
| 2 | 一个强调色 | 墨蓝 `#1e46d6` 只用于可交互与当前状态，绝不用于严重级别或图表分类 |
| 3 | 状态必须可读两次 | 颜色 + 文字（或图标）双重编码，色觉障碍与灰度打印下仍可判别 |
| 4 | 密度服务熟练用户 | 基准字号 13–14px、行高 40px、一屏可扫 12 条告警；不做大间距营销式排版 |

**反模式（明确不做）**：仪表盘式圆角大卡片嵌套、渐变色填充的面积图、把所有指标做成环形进度、
在深色主题里用纯黑 `#000` 背景与纯白文字（眩光）。

## 2. 信息架构

现状 20 个视图平铺，认知负担高。改为 **5 组、组内不超过 5 项**，一屏可见，不做二级折叠：

| 分组 | 条目 | 对应现有视图 |
|---|---|---|
| 监控 | 态势总览 | `OverviewView` |
| | 态势大屏 | `SituationView`（同一数据源的全屏变体） |
| | 告警队列 | `AlarmsView` |
| | 攻击视图 | `AttackView` |
| | UEBA 异常 | `UebaView` |
| 调查 | 日志检索 | `SearchView` |
| | 案件 | `CasesView` |
| | 资产 | `AssetsView` |
| | 端点 | `EndpointsView` |
| | 威胁情报 | `ThreatIntelView` |
| 检测工程 | 检测规则 | `DetectView` + `ParseRuleEditorView`（编辑器为规则二级页） |
| | 接入与解析 | `IngestView` |
| | 参考集 | `RefsetView` |
| | 元数据 | `MetaView` |
| 响应与合规 | 编排响应 | `SoarView` |
| | 通知 | `NotifyView` |
| | 报表 | `ReportView` |
| | 合规 | `ComplianceView` |
| 工作台 | AI 助手 | `AiAssistantView` |
| | 设计系统 | 本规范（仅原型内可见，不进入产品导航） |

登录页 `LoginView` 保持独立，不属于导航。

**为什么是单栏而不是「图标轨道 + 二级面板」**：20 项在 232px 单栏内可以完整呈现（约 760px 高），
省掉一次悬停/点击；图标轨道方案在 1440px 下要占用 64+208px，反而压缩了表格宽度。

**「态势大屏」保持独立入口**（已确认不与总览合并）：它的使用场景是墙面投屏与值班巡检，
密度、字号、交互假设都与桌面研判不同。合并成同一页的两种模式会让两种场景互相将就，
也会把大屏特有的「无导航、无写操作」约束带进总览。

## 3. 布局栅格

```
┌──────────┬──────────────────────────────────────────────┐
│ rail     │ topbar 56px（吸顶，半透明模糊）               │
│ 232px    ├──────────────────────────────────────────────┤
│ 可折叠至  │ main：padding 22/24，max-width 1560，居中     │
│ 62px     │  12 列栅格，gap 14                            │
└──────────┴──────────────────────────────────────────────┘
```

| 断点 | 行为 |
|---|---|
| ≥1321px | 4 列 KPI；趋势图 1.85fr + 分布 1fr；ATT&CK 1.35fr + 实体 1fr |
| ≤1320px | KPI 2 列；趋势/分布、矩阵/实体全部单列堆叠 |
| ≤1080px | 检索页字段面板默认收起，由标题栏按钮展开 |
| ≤860px | 导航改为 252px 抽屉（覆盖式）；命令面板入口收起；KPI 单列 |
| ≤560px | 队列表只保留「选择/严重/告警/时间」四列，标题两行截断，副标题省略 |

**验收视口为 1280–1920 桌面宽度**（1280–1320 采用 2×2 KPI 布局，属预期降级）。
1080 及以下仅为降级保证：不溢出、可滚动、可打开抽屉，
不承诺完整的移动研判体验（见第 11 节决策 3）。

侧栏折叠态宽度 62px，仅图标 + 悬停浮层提示（`data-label` 生成，不额外写 DOM）。

## 4. 设计令牌

令牌是唯一事实源：组件不写死颜色，主题切换只替换 `:root` / `[data-theme="dark"]` 两组变量。

### 4.1 语义色与实测对比度

对比度为 WCAG 相对亮度公式实算值（非估算），括号内为「在卡片面 `#ffffff` / `#16191f` 上」。

| 令牌 | 浅色 | 深色 | 用途 | 浅色实测 | 深色实测 |
|---|---|---|---|---|---|
| `--text` | `#14161a` | `#e8eaee` | 主文本 | 18.11:1 | 14.61:1 |
| `--text-2` | `#52545c` | `#a9afba` | 次级文本 | 7.55:1 | 7.99:1 |
| `--text-3` | `#6a6c74` | `#858b97` | 辅助/说明（≥11px） | 5.24:1 | 5.14:1 |
| `--accent` | `#1e46d6` | `#8fa6ff` | 交互、当前项、链接 | 7.24:1 | 7.60:1 |
| `--sev-critical` | `#c8102e` | `#ff8089` | CRITICAL | 5.88:1 | 7.29:1 |
| `--sev-high` | `#c2410c` | `#ffa07a` | HIGH | 5.18:1 | 8.85:1 |
| `--sev-medium` | `#8a5a00` | `#f0c05a` | MEDIUM | 5.93:1 | 10.39:1 |
| `--sev-low` | `#2f6fb0` | `#8fbcf5` | LOW | 5.22:1 | 8.95:1 |
| `--sev-info` | `#666b75` | `#9aa1ad` | INFO | 4.86:1 | 6.77:1 |

徽标采用「浅色底 + 深色字」同色系组合，全部通过 AA：

| 徽标 | 前景 / 背景（浅） | 实测 | 前景 / 背景（深） | 实测 |
|---|---|---|---|---|
| CRITICAL | `#c8102e` / `#fdeef0` | 5.23:1 | `#ff8089` / `#33191c` | 6.71:1 |
| HIGH | `#c2410c` / `#fdf0e8` | 4.64:1 | `#ffa07a` / `#33200f` | 7.80:1 |
| MEDIUM | `#8a5a00` / `#fdf6e3` | 5.49:1 | `#f0c05a` / `#302818` | 8.59:1 |
| LOW | `#2f6fb0` / `#eef4fb` | 4.72:1 | `#8fbcf5` / `#16232f` | 8.12:1 |
| INFO | `#666b75` / `#f2f3f5` | 4.82:1 | `#9aa1ad` / `#23262c` | 5.83:1 |

深色主题下主按钮使用「浅底深字」（`#8fa6ff` 填充 + `#0f1115` 文字，8.16:1），而不是白字压在亮蓝上
（后者仅约 2.2:1，是最常见的深色主题可读性事故）。

### 4.2 颜色使用规则

- **强调色不表达数据**：图表用 `--fill-*` 系列（与语义色同源但更饱和），避免用户把品牌蓝读成某一级别。
- **严重级别只出现在**：徽标、行首 2px 脊线、趋势图的告警曲线、ATT&CK 命中强度。其余位置不得使用红/橙。
- **中性层级**：`surface → surface-2 → surface-3` 三级底色承担层次，阴影仅用于抽屉、命令面板、Toast 等浮层。
- **焦点环**统一 2px `--accent` + 2px 偏移，任何自定义控件不得移除。

### 4.3 字体与字阶

- 无衬线：系统栈（`-apple-system` → `PingFang SC` → `Microsoft YaHei`），不引入 Web 字体，避免首屏抖动。
- 等宽：`ui-monospace / SF Mono / Menlo`，只用于 ID、时间、SPL、JSON、数值对齐。
- 所有数字启用 `font-variant-numeric: tabular-nums`，保证列对齐与扫读。

| 字号 | 字重 | 用途 |
|---|---|---|
| 26px | 600 | 页面标题（字距 −0.022em） |
| 20px | 600 | 移动端页面标题 |
| 16px | 600 | 抽屉标题 |
| 14px | 400/600 | 正文、导航、顶栏 |
| 13px | 400/500 | 表格主行、按钮、输入 |
| 12px | 400 | 表格次行、说明、标签 |
| 11px | 500/600 | 分组标题、KPI 标签（字距 +0.05em） |
| 10–10.5px | 500 | 表格表头（大写，字距 +0.07em）、等宽元数据 |

### 4.4 间距、圆角、动效

- 间距 4px 基准：2 / 4 / 6 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48。
- 圆角按容器层级递增：4（徽标/输入内元素）→ 6（按钮/输入/标签）→ 10（面板）→ 12（浮层）→ full（圆点/胶囊）。
- 动效：120ms（悬停/聚焦）/ 200ms（浮层淡入）/ 280ms（抽屉滑入），统一 `cubic-bezier(.2,.7,.3,1)`。
- `prefers-reduced-motion: reduce` 下所有过渡降为 0.01ms，包括运行期切换偏好。

## 5. 组件契约

| 组件 | 尺寸 | 状态 | 行为约束 |
|---|---|---|---|
| 主按钮 | 高 30（沿用既有 compact 控件契约） | 默认/悬停/按下/禁用/焦点 | 禁用降透明度 45% 且 `cursor: not-allowed`；不承担危险语义 |
| 危险按钮 | 同上 | 描边式，悬停才填浅底色 | 仅用于终止进程、隔离端点等不可逆动作，且必须二次确认 |
| 输入 | 高 32，内边距 9 | 默认/聚焦/错误/禁用 | 聚焦时边框变强调色 + 3px 柔光环；错误态附 `aria-invalid` 与就地说明，不用 Toast 报校验 |
| 筛选条 | 容器 padding 10，间距 8 | — | 搜索框 `flex:1`，其余自适应换行；筛选变化立即重查并写回 URL |
| 徽标 | 高 20，字号 10 | 5 级严重度 | 左侧 4×8 色条 + 文字，不省略文字只留颜色 |
| 状态胶囊 | 高 19，等宽 9.5px | OPEN/INVESTIGATING/RESOLVED/CLOSED/SUPPRESSED | 文案直接使用服务端词汇，不做中文改写以免与 API 对不上 |
| 表格 | 行高 ~40，表头 sticky | 悬停/选中/打开/焦点 | 行首 2px 色脊线标识严重度；标题用真实 `button` 承载 Enter/Space；整行点击作为鼠标增强 |
| 分页 | 高 26 | 当前页/禁用/省略 | 明确标注「第 1–12 条，共 N 条」；表头排序只作用于当前页时必须在界面标注 |
| 抽屉 | 宽 486（移动端 100vw） | 打开/关闭/有未保存草稿 | `aria-modal` + 焦点陷阱；关闭后焦点回到触发行；有草稿时 Esc 被拦截并给出原因 |
| 命令面板 | 宽 600，顶部 14vh | 空/有结果/无结果 | 真实 input 上 `role="combobox"`，列表常驻 `role="listbox"`；输入法确认不触发选择 |
| 空态 | 内边距 44 | 无数据/无匹配 | 一句原因 + 一个恢复动作（清除筛选 / 放宽时间），不放插画大图 |
| 骨架屏 | 与真实行同高 | 加载 | 保留布局尺寸避免跳动；只在首次加载使用，重查保留旧数据 + 顶部进度 |

## 6. 三个核心页面

### 6.1 态势总览 `/overview`

四段结构，自上而下回答问题：**现在有多糟 → 趋势如何 → 打在哪里 → 我先看哪条**。

1. **KPI 行（4 卡）**：待处置告警（含 CRITICAL 数）、平均确认时长 MTTA、受影响资产、24h 检测命中。
   数值 32px 等宽，变化量用带方向的胶囊（升红/降绿按“变好/变坏”判定，不按正负号）；
   卡片底部嵌入 32px 迷你趋势，**不替代**主图，只提示方向。
2. **趋势 + 分布**：24 小时事件量（面积）+ 告警量（虚线）双轴归一化，图例必须常显；
   右侧严重度分布含 INFO，用条形而非饼图（饼图在 5 类且数值接近时不可读）。
3. **ATT&CK 命中 + TOP 实体**：12 战术 × 3 技术，四级强度；空命中显示「·」而不是留白，
   避免用户误判为数据缺失。风险分用条形 + 数值，条长与分值同比例。
4. **最近告警**：5 行紧凑表，直接复用队列的行样式，点击进入同一抽屉。

新鲜度标签取四类数据源中最旧的成功时间；刷新中显示脉冲点，失败保留原时间并标灰——
不允许失败刷新产生新的成功时间。

### 6.2 告警队列 `/alarms`

- **默认视图 `ACTIVE`**（OPEN + INVESTIGATING），`ALL` 必须作为显式选项存在于 URL。
  原因是按时间倒序的混合队列会把未认领工作埋在新噪声之下。
- **保存视图标签**（待处置 / 我负责 / 全部）作为队列上方的第一层入口。它们不是新的 URL 键，
  只是既有过滤的快捷方式：待处置 = `status=ACTIVE`，我负责 = `status=ACTIVE&owner=mine`，
  全部 = `status=ALL`（显式取消状态过滤）。切换标签不改变其他过滤条件。
- 表头信息层级：严重 → 告警标题/规则 → 实体 → 风险 → 状态 → 负责人 → 时间。
  标题下附规则与告警 ID（等宽 10px），因为分析员对规则名的记忆强于随机 ID；
  风险分右对齐并对 ≥80 的高风险值做语义色强调。
- 批量操作在选中后出现于结果条右侧，显示「已选 N 项」；未选择时按钮禁用而非隐藏，保持位置稳定。
- 抽屉内固定在底部的三个动作：认领 / 转为调查中 / 查看原始日志。
  状态流转按服务端 `allowedTransitions` 渲染，当前态用强调底色标记。
- 证据时间线：时间（等宽）+ 事件点 + 描述 + 可复制的键值片段；命中检测的那一步用成功色收束。
- **行高固定 40px，不提供密度切换**（已确认「按美观设计」）：一屏 12 条是本产品信息量下的平衡点；
  密度切换会让不同页面的表格高度不一致，破坏跨页扫读的节奏。

### 6.3 日志检索 `/search`

- **草稿与已应用查询分离**：编辑不触发检索；`⌘/Ctrl+Enter` 或「运行」才生效。
  存在未应用修改时顶部出现提示条，明确告知「分页、导出与结果链接仍指向已应用的查询」。
- 结果区固定四层：时间直方图 → 统计条（条数/耗时/扫描量）→ 字段过滤胶囊 → 事件列表。
- 事件默认单行摘要（时间、级别、数据集、命令/消息、ATT&CK 标签），展开显示格式化 JSON，
  并给出「按主机过滤 / 按源 IP 过滤」的枢轴动作——过滤以胶囊呈现，可逐个移除。
- 字段字典在左，窄屏收起；点击字段把 `| stats count by <field>` 追加到草稿，而不是直接执行。
- 空态必须回显已应用的查询原文，并给出「改为近 7 天」这一条明确出路。

## 7. 交互与键盘

| 按键 | 行为 |
|---|---|
| `Tab` | 首个焦点为「跳至主内容」链接，直达 `#main` |
| `⌘K` / `Ctrl+K` | 打开/关闭命令面板 |

## 8. 无障碍结论

- 正文/次级/辅助文本、强调色、5 级严重度徽标、深色主题全部通过 WCAG AA 4.5:1（最小值 4.64:1，见 4.1）。
- 焦点环 7.24:1（浅）/ 8.16:1（深），超过 3:1 的非文本对比要求。
- 指针目标 ≥ 24×24（WCAG 2.2 AA），桌面主操作实际高度 26–32px。
- 手机端不在本期验收范围：仅保证不溢出、可滚动、可打开抽屉，不做写操作适配。
- 状态不单靠颜色：严重度有色条 + 文字，状态有圆点 + 服务端词汇。
- 表格有 `<caption class="sr-only">`，操作列有 `sr-only` 表头。
- 结果数量、认领结果通过 `role="status" aria-live="polite"` 播报。

## 9. 主题实现

**默认跟随系统**（已确认），三条规则决定优先级：

1. **首帧**：内联脚本在样式生效前写 `data-theme`，取值顺序为 `?theme=` 参数 → `localStorage['socp.theme']`
   → `prefers-color-scheme`，避免闪白。
2. **跟随**：未显式选择过主题时，监听 `matchMedia('(prefers-color-scheme: dark)')` 的 `change`，
   系统在页面打开期间切换深浅色会实时跟进（不需要刷新）。
3. **覆盖与恢复**：点击主题按钮即视为显式选择并写入 `localStorage`，此后不再跟随系统；
   命令面板「主题：恢复跟随系统」清除该键并立刻回到系统当前偏好，`title` 也会标明当前是否跟随。

其余实现约束：

- 组件只消费语义令牌；主题切换不重排布局，仅重绘图表（`renderCharts`）与令牌样张。
- 深色主题不使用纯黑背景（`#0f1115`）与纯白正文（`#e8eaee`），降低眩光与残影。
- 图表颜色取自 `--fill-*`，切换主题时同步替换，无需重建 SVG 结构。

## 11. 已确认决策

评审于 2026-10-21 确认，后续实现按此执行：

| # | 议题 | 决策 | 影响 |
|---|---|---|---|
| 1 | 态势大屏是否与总览合并 | **不合并**，保留两个独立入口 | 导航仍是 20 项；大屏可按投屏场景单独调整密度与字号，不牵连总览 |
| 2 | 深色是否作默认 | **跟随系统** | 首帧按 `prefers-color-scheme` 落主题；系统切换实时跟进；显式切换后记住，可从命令面板恢复跟随（见第 9 节） |
| 3 | 手机端支持程度 | **不作为本期范围** | 只保留降级保证（不溢出、可滚动、可开抽屉），不做移动写操作；验收视口 1280–1920 |
| 4 | 表格密度切换 | **不提供切换**，按美观与节奏固定 40px 行高 | 少一个全局偏好，少一套需要回归的状态组合 |
