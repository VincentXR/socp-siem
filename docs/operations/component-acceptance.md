# Component activation and acceptance

A running process or a green health endpoint establishes availability only. Keep separate
records for actual browser workflows, infrastructure delivery, code regression, and CI.
A component is operational only when its intended input produces an observable output;
recovery and authorization need their own checks. External integrations require an authorized
real destination. Do not substitute fixtures for external delivery or production certification.

The Vue workbench supplies actual click/form/upload/download workflows. The FILE/Vector
collector supplies real event input. Kafka Streams comparison code is test-scoped; it is not
the production detection engine. Do not deploy test libraries just to mark every module active.

Native binaries extracted from pinned OCI images can validate local component protocols
when container storage is constrained. Record image/platform/binary provenance and adapted
paths. This does not establish Kubernetes scheduling, container hardening, HA, or production
retention. Production sizing, enterprise IdP policy, real endpoints and vendor delivery remain
separate acceptance boundaries.

## Enable the optional local observability stack

The base Compose file mounts Grafana provisioning and persistent Loki/Jaeger storage.
Jaeger runs as upstream UID 10001 and stores Badger under its writable `/tmp` volume.
For an existing volume, review ownership and back up its contents before changing mounts;
this configuration does not migrate previously stored traces automatically.
The observability overlay adds rules, Alertmanager routing and application log shipping.
The regular event collector and log collector must have distinct checkpoint directories.

Create a dedicated directory containing only the fourteen application stdout files named
`<service>.log`. The reader UID/GID must read those files and write its separate spool;
create the spool with that ownership before starting Compose. Review application log
redaction before shipping logs to another trust boundary. The collector uses device/inode
identity because identical startup banners must not collapse different service files.
It uses the generic HTTP sink supported by the verified Vector build, one Loki JSON push
document per request, durable buffering, acknowledgements and backpressure.

Prepare an authorized monitoring webhook URL in a private file, not in a command line or
tracked `.env`. Set `SOCP_MONITORING_WEBHOOK_URL_FILE`, `SOCP_APPLICATION_LOG_DIR`,
`SOCP_LOG_VECTOR_DATA_DIR`, and optionally `SOCP_LOG_READER_UID/GID`. Load the catalog
and existing integration credentials through the normal deployment configuration, then run:

```sh
docker compose --env-file infra/middleware-images.env \
  -f infra/docker-compose.yml -f infra/docker-compose.observability.yml \
  --profile extra --profile observability up -d
```

Ensure `SOCP_SECURITY_METRICS_TOKEN` matches the mounted metrics token and enable
`SOCP_TRACING_ENABLED=true` with the authorized `SOCP_OTLP_ENDPOINT`. The reactive
gateway initializes its own SDK before creating or forwarding spans; it does not use the
servlet tracing filter. Validate actual exported gateway spans as well as downstream spans. Detection captures
caller context per bounded rule-queue item and persists it in the alert outbox; scheduled
HTTP delivery restores that saved context before forwarding. Verify a new collected event
reaches Alert Web in the same trace, not merely the earlier Kafka/indexing span tree.
Alert migration V26 adds a nullable parent-context field to durable deliveries so later
enrichment/automation calls keep actual parents. Existing rows stay compatible, but their
historical parent spans cannot be reconstructed. The migration preserves claims and is
compatible with an older application binary; rolling back the binary does not require
dropping the added column. Native integrated
launches using a `pg` or `prod` profile default to Redis rate limiting with fail-closed behavior;
H2-only local development retains its process-local default. Explicit overrides remain subject
to production guards. The five role-specific Helm readiness groups include Redis and bound
its connection/command wait to 500 ms; startup/liveness remain independent of asynchronous
sinks. Do not add OpenSearch to ingestion API readiness: durable ingress must survive an
indexing outage.

Validate configuration, targets and the two provisioned dashboards before fault injection.
Stop only a verified disposable local service, wait for the unchanged one-minute rule,
observe the receiver, restore the identical artifact/configuration, and verify resolved delivery.
Never stop shared Redis or a production service for this exercise. Close browser contexts
to finalize local recordings; distribute reviewed screenshots and metadata only, excluding
passwords, TOTP enrollment material, tokens, raw recordings and unredacted logs.
